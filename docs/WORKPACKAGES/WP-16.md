# WP-16: weather information (optional service)

Branch `feat/WP-16-weather`. Milestone after S-M5 (optional per Art.
3(3); `07 §2` U-08 "kept, deferred"). Owns `internal/weather/`, the
endpoint `GET /v1/weather`, the `weather_products` table (queries), the
`weather_checked_ref` fill on intents (through an interface WP-7 left
nil). Depends on WP-7. Consumers: WP-17 (portal planning page), WP-18.

## Read first

1. `docs/PLAN.md §1` S6, `§6.1`, `§15` Q12.
2. Spec `01 §3` S6 (the minimum content: wind direction and speed in
   m/s with gusts, lowest broken/overcast layer in hundreds of ft AGL,
   visibility, temperature and dew point, convective and precipitation
   indicators, observation or forecast location and time, QNH with its
   area), Art. 10(3) (use weather where applicable), `09 §1.1` Art. 12
   row.
3. LESSONS E-02 (no source configured must be visible, not an empty
   product), E-13 (units in names: `wind_speed_ms`, `gust_ms`,
   `cloud_base_ft_agl` is the regulation's unit and is named so,
   `visibility_m`, `temp_c`, `dew_point_c`, `qnh_hpa`).
4. Reference only: utm `TASKS.md` U-08 (METAR + thresholds as
   configuration).

## What to build

- `weather.Source` interface (`Fetch(ctx, area) ([]Product, error)`)
  with one implementation: METAR/TAF from a configured URL
  (`USSP_WEATHER_SOURCE`, the NOAA Aviation Weather Center data API
  format for the stations configured per area in `policy.WeatherStations`),
  parsed into the Art. 12(2) fields with the units above; convective
  (`TS`, `CB`) and precipitation (`RA`, `SN`, ...) indicators from the
  report groups; `observed_at`/`valid_from/to`; QNH with the station as
  its area. Poll every `policy.WeatherRefreshS` (600 s); products stored.
- `GET /v1/weather?bbox=&at=` (scope `ussp.geo`): the products whose
  area intersects the bbox, newest first, with `age_s`; no source
  configured → `503 weather_unavailable` with `reason: not_configured`;
  source failing → the last products with `stale: true` and the failure
  time (E-02 both).
- `weather_checked_ref` on an intent: at decision time WP-7 calls
  `weather.Check(ctx, envelope, window)` which records the product ids
  consulted (no judgement: the regulation says "use", the thresholds an
  operator applies are theirs; a `policy.WeatherAdvisory` wind threshold
  produces a `conditions[]` entry `weather_advisory` on the decision,
  never a rejection).

## Done when

- [ ] A fixture METAR set parses to the exact fields (table test with
  every group kind, including a missing dew point and a `CAVOK`).
- [ ] E-02: not configured → 503 with reason; configured and the fake
  source down → stale products with time; up → fresh.
- [ ] An intent decided with a product in force carries its id in
  `weather_checked_ref`; without a source, null and a `conditions[]`
  entry `weather_unavailable`.
- [ ] Lint, race, coverage ≥ 85 % on `weather`; `CHANGELOG.md`; PR with
  outputs.

## Safety notes

- Weather never rejects an intent and never commands anything; an
  advisory is a condition the operator reads.
- Units in every field; the cloud base is in hundreds of feet AGL
  because the regulation says so, and the name says so.
