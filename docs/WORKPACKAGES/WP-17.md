# WP-17: operator portal (web)

Branch `feat/WP-17-web-portal`. Milestone S-M1 (register, clients,
intents, decisions, geo map), S-M3 (traffic and alerts). Owns `web/`
except the console routes (WP-18): the app shell, BFF routes under
`/_bff/*`, i18n catalogues, the portal pages, Playwright smoke tests.
Depends on WP-0 (bootstrap), WP-2 (sessions), WP-7, WP-12 (API shapes;
start against the OpenAPI file as soon as WP-7's PR is open, with the
generated types and a mock server from the file), WP-11 (traffic
pages). Consumers: operators; the lab's demo.

## What to build

- Shell: `uspace-ui` theme (npmjs, exact pin: ≥ 0.2.0 for the intents
  pages, ≥ 0.3.0 for the traffic pages; reconciliation M32, M33),
  `pnpm` with `packageManager` pinned (M34), navigation, locale switch
  (`ka` default, `en`), session from the BFF cookie (`/_bff/login`
  posts to `/v1/accounts/login`, sets `uspace_session` and `uspace_csrf`;
  `/_bff/logout`; every API call from the browser goes through
  `/_bff/api/*` which forwards the cookie's bearer and the `X-CSRF-Token`
  header; no token in browser storage; M21). The kit's
  `sessionClaimsUnverified` yields `{sub, roles: string[], realm, exp}`
  (M20). The kit's CSP (`connect-src 'self'`, `font-src 'self'`,
  `worker-src blob:`), fonts via `next/font/local`, the basemap at
  `/basemap/` served by the deployment's Caddy from the lab's bundle; no
  third-party tile or font request (M38).
- Live feeds: the browser opens `WS /v1/traffic` and `WS /v1/alerts`
  directly on the same origin with the session cookie; no ticket route,
  the BFF does not proxy WebSockets (M22); the kit's `live` client
  parses the console frame (envelope + `body`; `console/status/v1`
  carries `degraded[]`, `dropped_frames` and the thresholds the pages
  display; M29); a `4401` close sends the user to login.
- Pages (operator roles):
  - Register: registration number, display name, email → `pending_validation`
    state shown with what the authority answered (status only).
  - Clients: create (secret shown once), rotate, bind serials, scopes.
  - Intents: a form for the ten Annex IV items with volume drawing on
    the MapLibre map (polygon or circle from the kit; the drawn
    geometry is sent as F3548 `Volume4D` with W84 altitudes; the page
    does no geometry math: the API returns the AMSL derivation and any
    problem by field path), time window, priority (special operation
    only with the flight type), contingency, emergency contact
    reference; decision view (number, thresholds, conflicts with the
    item named, conditions, versions with `change_reason`), activate /
    modify / end actions; list with states.
  - Geo: the map with zones, airspaces (requirements in a side panel)
    and restrictions for the viewport from `/v1/geo`, each with
    `updated_at`, `version`, validity; `stale` banner with age when the
    API says so; `geo_changed` refetch over the WS.
  - Traffic (S-M3): for an intent, the live product on the map with the
    kit's symbology (trust class, age, identification status), the
    `degraded[]` banner (each input with its time), proximity alerts
    with numbers and the peer, acknowledgement; the alerts list with
    repeat and escalation state; `dropped_frames` shown when > 0.
  - Weather (after WP-16): products for the planning area or the
    "not configured / stale" state.
- i18n: every string in both catalogues; a build-time check fails on a
  missing key; dates and numbers through the locale with explicit units
  (`m`, `m/s`, `ft AGL` where the regulation's unit applies).
- Errors: every form renders the shared problem body (`errors:
  [{field, reason}]`, `truncated`; M28) through the kit's form helpers;
  a refused intent's `conflicts[]` come from the decision body, not the
  problem.
- Tests: ESLint (no geometry imports, no hand-written API types, no
  `pg`/`nats`), `tsc --noEmit`, Playwright smoke against `cmd/ussp-dev`
  with the fakes: login, file an intent, see the decision, open geo,
  see traffic for a running simulated flight, acknowledge an alert, both
  locales.

## Safety notes

- The portal renders what the API says; every judgement number on
  screen comes from a response field, never computed in the browser.
- An alert is shown with its numbers and the other aircraft; the
  pilot decides. No advice, no automation hooks.
