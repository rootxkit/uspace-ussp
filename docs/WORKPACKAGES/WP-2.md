# WP-2: auth and accounts

Branch `feat/WP-2-auth-accounts`. Milestone S-M1. Owns `internal/auth/`,
`internal/accounts/`, the endpoints `POST /oauth/token`,
`GET /.well-known/jwks.json`, `/v1/accounts/*`, the scope middleware's

projector interface; until WP-6 merges, an in-memory projector).

## What to build

- `internal/auth`:
  - `Ecosystem`: a `core/auth.Verifier` configured with the authority's
    issuer (`USSP_TOKEN_ISSUER`, `USSP_TOKEN_JWKS_URL`) and `aud =
    USSP_SYSTEM_ID`; `RequireScope` middleware returning problem+json
    401/403 with the `TokenError.Counter` name as `type`; every refusal
    audited (actor = `sub` when parseable, else `unknown`).
  - `Operator`: our own `core/auth.Issuer` from `USSP_ISSUER_KEY_FILE`
    (PEM; generated by `scripts/gen-issuer-key.sh` into `local/`,
    git-ignored), `kid` = key fingerprint, JWKS served with the current
    and the previous key during rotation (`USSP_ISSUER_PREVIOUS_KEY_FILE`),
    `POST /oauth/token` with `grant_type=client_credentials`, basic or
    body client auth, argon2id secret check in constant time, scopes
    granted ∩ requested, TTL `policy.OperatorTokenTTLS` ≤ 3600, `aud =
    USSP_SYSTEM_ID`, `jti` ULID; issuance and refusal audited; a
    per-client and per-IP token-rate limit.
  - `Session`: staff and portal sessions as RS256 JWTs from the same
    issuer with `scope=session:<role>` and 12 h TTL, the BFF cookie
    contract documented for `web/` (name, `HttpOnly`, `SameSite=Strict`,
    CSRF double-submit header).
  - `Bindings`: `client_serial_bindings` reads and the `client_bindings`
    projection (`client_id → []serial_fold`).
- `internal/accounts`: operator self-registration (`POST
  /v1/accounts/operators` with the registration number; status
  `pending_validation` until WP-5's registry check says `valid`, which
  the handler calls through an interface and treats `unknown` as
  pending), `operator_admin` / `remote_pilot` / `viewer` roles,
  `POST .../clients` (secret shown once, operator notified by the audit
  event for now), `POST .../clients/{id}/rotate` (old secret valid for
  `policy.ClientSecretOverlapS`), serials bound and unbound with
  `core/serial` validation, staff accounts with argon2id and TOTP MFA for
  `admin`, `POST /v1/accounts/login` with a per-account and per-IP
  limiter (lockout 15 min after 10 failures, audited), `/logout`, `/me`.
- `api/openapi.yaml`: the `accounts` and `auth` tags with every path
  above and the `Problem` types they return.

## Safety notes

- A token proves who sent a message, not that it is true (06 §1). Nothing
  in this WP marks data trusted; trust classes are WP-8's.
- Never log a token, a secret or a session cookie. Error texts never
  contain the token (core guarantees this for its errors; keep it for
  ours).
- The verifier is shared across requests; its JWKS refresh runs under
  `context.WithoutCancel` (core does this; do not wrap it in a request
  context).
