## What to build

- `manned.ANSPStream`: WebSocket client to `USSP_ANSP_STREAM_URL`
  with mTLS (`USSP_ANSP_MTLS_CERT/KEY/CA`) and an ecosystem token
  (`ansp.traffic`), `bbox` = the U-space airspaces' union padded by
  `policy.MannedMarginM` (5 km) or a configured bbox; bootstrap from
  `/snapshot`; each frame `manned_track.v1` (consumed schema from the
  lab's published copy; validated, unknown fields ignored) → `track/manned/v1`
  on `man.v1.<cell3>.<cell5>.<icao24>` with `trust: surveillance`,
  `source: ansp_feed`, `source_instance: <adapter id>`, `captured_at`
  by `PlaceNetwork` against the frame's `ts`; reconnect forever; after
  `policy.MannedUnavailableS` (10 s) without a frame → `src.v1` state
  `unavailable since T` (WP-11 shows it), counters.
- `manned.Econspicuity`: adapter reading an ADS-B source
  (`USSP_ADSB_SOURCE`: `http://<host>/data/aircraft.json` polled at 1 Hz,
  or `sbs://<host>:30003` BaseStation lines), decoding only the fields
  the schema has (`icao24`, `callsign`, position, `alt_pressure_m` from
  the barometric altitude in feet × 0.3048, `alt_wgs84_m` when the feed
  gives geometric altitude, `gs_ms`, `track_deg`, `vrate_ms`, `emergency`
  from the squawk 7500/7600/7700 or the feed's flag), `trust: broadcast`,
  `source: adsb_rx`, placed at arrival with the feed's `seen` age
  subtracted (T-12); AMSL for separation from `alt_wgs84_m` via the
  geoid when present, else pressure altitude with the margin (R-08/R-09,
  `alt_source: pressure`); a recorded file replay mode for the lab
  (`file://...jsonl` with original timestamps re-based).
- `peers.Views`: for each configured area of interest (same as WP-13's
  subscriptions, tiled to ≤ 7 km diagonals), a DSS subscription for ISAs
  (`PUT /rid/v2/dss/subscriptions/{id}`, ≤ 24 h, renewed) and the ISA
  search (`GET /rid/v2/dss/identification_service_areas?area=`); ISA
  notifications from WP-9's receiver update the set; for every ISA whose
  `uss_base_url` is not ours (discovery, never configuration: `00 §7`),
  one poller per view: `GET {uss_base_url}/uss/flights?view=` at 1 Hz
  with `rid.display_provider`, one in-flight request, deadline 3 s, a
  slow SP (> p99) polled at 0.5 Hz with `age_s` shown; flights →
  `track/telemetry/v1` on `peer.v1.<cell>.<rid_flight_id>` with `trust:
  provider`, `source: network_rid`, `source_instance: <uss_base_url>`,
  `captured_at` by `PlaceNetwork` (older than 60 s → not shown,
  counted), identification by `ResolveBroadcast` over WP-5's lookup
  (basis `as_broadcast`: a peer's claim about its operator is not ours
  to vouch for, R-14); `peer_flights` rows via `tsdb-writer`; a peer
  that fails → its flights marked `peer_unavailable` in the product for
  `policy.PeerUnavailableS` then aged out, counter and `src.v1`.
  Details (`/details`) fetched only for views ≤ 2 km when the console
  asks (not on the 1 Hz path). Peer SP response bodies through core's
  bounded unmarshal; flights per response capped by `policy.PeerFlightsMax`.
- Source switches: types `ansp_feed`, `adsb_rx`, `network_rid` with
  instances; disabled → the adapter stops polling or closes the stream
  at once (SC-16: the SP's request count stops), tracks age out
  `source_disabled`.

## Safety notes

- A broadcast is never authenticated and every product says so (R-05);
  a peer's flight is `provider`, never upgraded to `authenticated`.
- An empty sky is never shown as clear: every input has a state with a
  time, and the product's `degraded[]` carries it (02 F4).
- No configured peer address anywhere; a test greps config for a USS
  base URL other than ours and the DSS.
