# WP-18: USSP console (web) and admin API

Branch `feat/WP-18-web-console`. Milestone S-M5. Owns `web/` console
routes (`/console/*`), `internal/admin/` and the `/v1/admin/*` endpoints
of PLAN §6.1, the emergency workflow. Depends on WP-17 (shell, BFF),
WP-11 (alerts, traffic by bbox), WP-13 (DSS state), WP-15 (undelivered
items, occurrences), WP-1 (policy, sources writers). Consumers: USSP
staff (`supervisor`, `support`, `admin`); the lab's demo.

## Read first

1. `docs/PLAN.md §3.1` (console feed = `traffic-ws` by bbox), `§6.1`
   (`/v1/admin/*`), `§15` Q15.
2. Spec `01 §3` S11 (emergency management plan and communication plan;
   the console's emergency workflow implements it), users table (staff
   roles), `02 F5` (unacknowledged critical alerts escalate to the
   supervisor console), `05 §6` (what the console must show when a
   process or a source is down: `monitor` down → "conformance and
   traffic alerts stopped since T"), `04 §3.6` (`source/status/v1`),
   `07` S-M5 done-when (flights, alerts, DSS state, degraded inputs,
   emergency workflow), LESSONS B-11 (disabled, healthy, stale, never
   heard, each distinct), E-02, SC-08 (switches, 403 for a viewer,
   audit), SC-22 (an empty console must never look like an empty sky).

## What to build

- `internal/admin` endpoints (staff sessions; `supervisor` for actions,
  `support` read-only, `admin` for policy and sources):
  `GET /v1/admin/flights` (active flights with intent, state,
  conformance, last sample age, source instance), `GET /v1/admin/alerts`
  (active and recent, escalations), `GET /v1/admin/dss` (`dss_state`,
  outbox depth, subscriptions, last errors, `uss_availability`),
  `GET /v1/admin/inputs` (every source type and instance with
  `disabled by <who> at <when>`, `healthy`, `stale since`, `never heard`,
  `lagging lag_s`; the CIS version and age; registry feed age; the
  monitor's status line fields including `evaluation_period_s`;
  terrain and geoid presence), `GET /v1/admin/escalations`, `POST
  /v1/admin/alerts/{id}/escalate|close` (audited, with reason), the
  emergency workflow: `POST /v1/admin/emergency/{flight_id}` opens a
  case (operator contact reference resolved by the authority: the
  console shows the reference and the authority's contact procedure;
  this WP does not fetch PII), notes with timestamps, the flight's
  record link, `close` with outcome; every step audited; `GET/PUT
  /v1/admin/policy` (new version with reason; the diff shown), `GET/POST
  /v1/admin/sources` (switch by type or instance with reason; 503 when
  the KV refuses, B-09; 403 for non-admin), `GET /v1/admin/occurrences`
  (undelivered with time to deadline), `POST /v1/admin/occurrences`
  (flag an event as an occurrence → WP-15), `GET /v1/admin/records/days`.
- Console pages: the live map by viewport over `traffic-ws` (the
  staff `uspace_session` cookie on a same-origin upgrade, M22; the
  console frame of M29: `console/subscribe/v1 {bbox, layers[]}` on each
  viewport change, `console/snapshot/v1` on connect, `console/status/v1`
  every 2 s feeding the inputs strip from `sources[]` and `degraded[]`,
  `traffic/product/v1` and `alert/v1` bodies; `realm: console` and
  `roles[]` from the session claims gate the pages) with the kit's
  symbology (`uspace-ui` ≥ 0.3.0) and a persistent inputs strip (each
  input's state with time; a down `monitor` shows "alerts stopped since
  T"); flights
  table; alerts with acknowledgement state, repeat count and escalation;
  DSS panel; inputs page with switches and audit; policy page with
  version history; emergency workflow pages; occurrences and records
  pages; `ka`/`en`.
- Tests: Playwright: an alert escalates and appears; a source switched
  off shows `disabled by` and its tracks age out `source_disabled`; a
  viewer gets 403 on a switch; the console loads with NATS down and
  shows every input `unknown` with the time (E-02, SC-22); DSS down
  panel; an emergency case opened and closed with audit rows visible.

## Safety notes

- The console has no button that reaches an aircraft. The emergency
  workflow is a communication checklist with timestamps, not a control
  panel.
- A switch is audited and reversible; a disabled input is labelled with
  who and when; nothing disappears silently.
