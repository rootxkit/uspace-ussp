# WP-18 runs: the USSP console

The brief's done-when is checked by the browser tests of
`web/e2e/console.spec.ts` against the e2e stack (`test/e2e/stack`: the
seven processes of `cmd/ussp-dev` on real PostgreSQL + PostGIS,
TimescaleDB and NATS, with the fakes of `internal/testfakes` (CISP,
authority token service and registry, ANSP coordination inbox and
manned stream, the simulated operator clients) and
`internal/dss/fakedss`; one same-origin front as Caddy routes it). For
WP-18 the stack adds the ANSP fake, a control route that makes staff
accounts (an admin's TOTP secret answered once, the test computes the
codes) and one that switches each fake down and up again, and a TCP
proxy in front of NATS that every process goes through, so a test cuts
the bus. CI's `web` job runs the suite on every pull request and uploads
the traces and screenshots (`playwright-traces`).

The API side is covered by `test/integration/console_test.go` (the
alerts' escalation and close, the emergency workflow, the policy, the
source switches with 403 and 503, the monitor's status) and
`TestIntegrationStaffAdminMFAStep`, run by `make integration`.

## Found on the way

- The kit's BFF proxy serves only its fixed `/_bff/api` prefix; the
  console's route hands the request to it under that prefix (PLAN §15
  Q30, `KIT: pending uspace-ui`).
- The browser tests sign in many times from one address; the stack
  raises `USSP_LOGIN_RATE_PER_MIN` (the budget keeps its own
  integration tests).
- A switched-off type disables an instance whose own row is on (core's
  sources model); the inputs page first had the instance win, and now
  asks `uspace-core/sources` (unit test `TestInputsSwitches`).
