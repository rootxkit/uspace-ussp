# WP-15 runs: coordination with the ANSP, records, occurrences, operating status (S-M2, S-M5)

The brief's lab clauses are S-M2 "the lab ANSP acknowledges the notice"
and the S-M5 done-when (records, occurrences, notices). What was run:

- **Run 1** (below): the S-M2 clause against the **real uspace-ansp
  api**, built from the commit `api/clients/SOURCE` pins (`7fc3ef1`),
  on its own migrated databases, with a lab issuer minted in the test.
  The test is `test/integration/lab_ansp_test.go` (build tags
  `integration lab`, skipped without `LAB_ANSP_BIN`).
- **Run 2** (below): the done-when **in process** against the real
  PostgreSQL + PostGIS, TimescaleDB and NATS JetStream with the fakes of
  `internal/testfakes` (`ansp`, `authority`): `coordination_test.go`,
  `records_test.go`, `retention_test.go`, `occurrence_test.go`,
  `status_test.go` under `test/integration/`; the unit forms are the
  tests of `internal/coordination`, `internal/records`,
  `internal/occurrence` and `internal/status`.

Not run: the lab's full systems profile (`uspace-lab` deploy/systems,
the four images with SITL) with this branch's image; the clause above
was run against the ANSP binary instead, outside a container. The
manned-traffic stream scenario (`ansp-inv02-manned`) is not this work
package's: see "USSP_ANSP_STREAM_URL" below.

## Decisions and gaps recorded here

- **Occurrence delivery (H-1, closed 2026-10-05).** Until then the
  pinned authority OpenAPI (`db84edc`) had no `POST /v1/occurrences`, so
  nothing delivered, and the queued body named the class `kind` where
  the authority's `OccurrenceReport` requires `category`: every report
  would have been a 400. The copy is now pinned at `e0e61ab`, the client
  is generated from it (`internal/occurrence/authclient`,
  `createOccurrence` only) and takes the `Deliverer` seat when
  `USSP_AUTHORITY_BASE_URL` and the token client are configured; a body
  queued before names `kind` and is mapped. The authority's idempotency
  key is (token `sub`, `report_ref`) in the body; its contract declares
  no `Idempotency-Key` header, so none is sent. The retry bounds
  (`USSP_OCCURRENCE_MAX_ATTEMPTS` 50, `USSP_OCCURRENCE_BACKOFF_MAX_S`
  600) are the spec's bounded-retry rule with this repository's
  defaults, pending GCAA; the 72 h deadline is 376/2014 Art. 4(8),
  itself open with GCAA (spec Q9). The lab run is Run 3.
- **The authority's client id form** (`ussp-<code>-<nn>`, an
  alphanumeric code, M24) refuses `ussp-USSP-DEV-01`, the client id of
  the default `USSP_SYSTEM_ID` `USSP-DEV`: the lab run uses the code
  `USSPLAB`. A deployment's code is the one on its certificate.
- **Alerts, intents, conformance states: no removal job** (5 years,
  `record_retention_days`): nothing in the system is that old; the job is
  owed before it is (spec 05 §4).
- **`operator_position`** is held past its retention only for flights an
  occurrence report names (`record_holds`); this USSP has no incident
  flag of its own (the authority's incidents are the authority's).
- **The Annex V `sent_at`** is the time the notice was built: every try
  posts the same bytes (the ANSP refuses a notice_ref with another body).
- **Readiness of a process test.** `/readyz` of api now lists
  `ansp_coordination`, `occurrences`, `records` and `operating_status`.
  Their state follows rows other tests leave in the shared database, so
  the process tests of `test/integration` check they are present and do
  not judge them (`withoutWP15`); their own tests do.

## USSP_ANSP_STREAM_URL

monitor reads the ANSP's manned-traffic stream (`ANSPFeed`,
`internal/app/monitor/anspfeed.go`) with a token of scope
`ansp.traffic` for the ANSP's origin and mTLS per `USSP_MTLS_MODE`,
reconnecting with a bounded backoff (1 s to 30 s); one frame is bounded
at 64 KiB. `ansp_feed` on `/readyz` says connected since T, unavailable
since T (no connection, or no frame for 10 s), or degraded with the
ANSP's own list from `console/status/v1` (a new connection forgets the
old list). Unknown schemas and unreadable frames are counted and skipped.

The manned tracks are **counted and held**, not published to `man.v1`:
they reach the CPA path with WP-14, after its echo guard keeps one of
this USSP's own flights heard back from the ANSP from being judged as a
second aircraft (PLAN §15 Q23). `/readyz` says so on every answer. Tests:
`TestANSPFeed`, `TestANSPFeedRefused` (unit, against an in-process
WebSocket); not run against the real ANSP's stream.
