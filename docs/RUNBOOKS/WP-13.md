## Found by the lab run

- The DSS refused a constraint query made with
  `utm.strategic_coordination`: `queryConstraintReferences` takes
  `utm.constraint_management` or `utm.constraint_processing`. Fixed, and
  `TestClientScopesMeetTheStandard` now checks every call's scopes
  against the pinned file's `security`.
- Not fixed here (owned elsewhere): the lab issuer's client is
  `ussp-USSP-DEV-01`, while `auth.ClientIDFor(USSP-DEV)` gives
  `ussp-ussp-dev-01` (M24); the api process would not get a token from
  the lab issuer. The lab run sets the client id directly. Run 3 puts a
  broker in front of the issuer instead, so that the api process runs
  with the derived id while the DSS records the lab's; since the review
  fixes our identity is the manager the DSS records (`dss.Client.Self`),
  whatever the configuration derives.
