## Found on the way

- `intent_active` never carries a flight's id (`flight_id` stays null),
  so traffic-ws did not mark the subscriber's own flight `own`. The
  product now also takes the flight that flies the subscribed intent as
  its own (`traffic.Area.OwnIntent`).
- An alert acknowledged before api has recorded its flight is
  `404 alert_not_found` for a short while. The portal's acknowledgement
  falls back to the intent the alert names; the machine client's
  acknowledgement keeps its query (unchanged, the same race). The page
  shows the refusal and a second press succeeds.
- `cmd/ussp-dev` gives every process one configuration, but api must
  not list its own issuer in `USSP_TOKEN_ISSUERS` while telemetry-ingest
  and traffic-ws must (to verify operator tokens and portal sessions).
  The e2e stack runs the seven processes with their own configurations.
