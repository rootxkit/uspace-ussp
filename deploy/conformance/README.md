# Conformance profile (WP-19)

How this USSP is run against uspace-lab's conformance suite (lab WP-L7,
`cmd/conformance`; spec `00 §7`), and the stack the chaos procedure of
spec `05 §6` runs on (`docs/RUNBOOKS/chaos.md`). The lab owns the suite,
its pass criteria, the `uss_qualifier` configurations and the third-party
onboarding procedure; this directory is the USSP's hook into it.

```
make conformance            # build this checkout's image, start the stack, run the suite, stop the stack
make conformance-selftest   # the hook in each of its states, no Docker (CI runs it)
make conformance-down       # remove a stack left running by CONFORMANCE_KEEP=1
```

`LAB_DIR` names a uspace-lab checkout (default `../uspace-lab`);
`SOURCE` names the lab commit this profile was written against and
records what that commit pins. The exit status is the suite's: 0 pass,
1 a gate requirement failed, 2 a configuration error (found before
anything is built or started), 3 incomplete (a gate requirement was not
checked; the report says which and why). The reports, signed with the
stack's issuer key, are under `local/conformance/reports/<run>/`
(git-ignored) with `run-info.txt` (the commits, the image id, the
push setting) and `issuer-jwks.json` to verify the signature
(`conformance verify --report R --jwks issuer-jwks.json` in the lab).

## Files

| File | What |
|---|---|
| `target.yaml` | the USSP's conformance target in the lab's format (`conformance/targets/README.md` there): every host and secret a `${VAR}` the hook fills |
| `authority-push-off.yaml` | the declaration that `openAuthorityFlights` is not applicable while `USSP_AUTHORITY_PUSH=off` (below) |
| `compose.yaml` | the overlay on the lab's systems stack: `USSP_AUTHORITY_PUSH` on rid-sp |
| `chaos.sh` | one row of the chaos procedure against a running stack (`docs/RUNBOOKS/chaos.md`) |
| `SOURCE` | the lab commit, the images it pins, the geoid's URL and digests |
| `../../scripts/conformance.sh` | the hook (`make conformance`): validation, stack, declaration check, suite |
| `../../scripts/conformance-selftest.sh` | the hook's own tests |

## The stack

The lab's systems stack (lab WP-L6: `deploy/compose.yaml` with the
InterUSS DSS and its CockroachDB by digest and the lab issuer,
`deploy/systems/compose.yaml` with the lab Caddy and its CA), composed
with `compose.yaml` here as project `uspace-ussp-conf`, the image under
test in place of the lab's USSP image. The state (the lab CA, every key
and password, the issuer's client secrets) is generated by the lab's
`gen-secrets.sh` into `local/conformance/state/` (git-ignored); nothing
is written into the lab checkout. The suite reaches the stack's hosts at
127.0.0.1 through the target's `resolve` and `ca_file`; nothing on the
machine changes.

- `CONFORMANCE_SYSTEMS=ussp` (default): the USSP's seven processes, its
  database and NATS, the DSS, the issuer and the Caddy. The authority,
  the CISP and the ANSP are absent, and the USSP says so on `/readyz`.
- `CONFORMANCE_SYSTEMS=all`: also the authority, the CISP and the ANSP of
  the lab's stack, for the chaos procedure (the ANSP image is the one the
  lab's `deploy/demo-up.sh` builds; the hook refuses to start without it).

Before the suite, the hook checks the declared `USSP_AUTHORITY_PUSH`
against what rid-sp answers to an upgrade without a credential (404 off,
401 on) and stops on a mismatch. With `CONFORMANCE_KEEP=1` the stack is
left running (`make conformance-down` removes it and checks nothing is
left); otherwise it is removed after the run, also after a failure.

The safety check of the profile: a target whose `USSP_SYSTEM_ID` (the
lab's `USSP-DEV`, or `USSP_CONFORMANCE_SYSTEM_ID`) contains neither
`TEST` nor `DEV` is refused before anything starts. Nothing in the stack
reaches an aircraft.

### Measured (2026-10-05, Windows 11, Docker Desktop 28.5.1, 16 CPUs and 7.7 GiB for Docker)

| | `ussp` | `all` |
|---|---|---|
| time, clean checkout with the images present (build, start, suite, stop) | 70 to 90 s | about 4 min to the suite |
| memory, idle, one `docker stats` sample | about 0.7 GiB (CockroachDB 0.3, the USSP's database 0.1, each Go process 25 to 50 MiB) | about 2.6 GiB |
| disk, images pulled the first time | about 2.5 GB (`timescaledb-ha` 1.1, CockroachDB 0.4, the DSS, NATS, Caddy, the Go build image for this checkout's image) | about 3 GB with the three other systems' images |

The demo profile's budget (4 vCPU, 7.6 GB, about 18 GB free on the
droplet) holds both; the profile runs on a laptop or in CI and never on
the droplet.

## Geoid

Every system of the stack reads GeographicLib's EGM2008 2.5' grid
(`egm2008-2_5.pgm`, 75 MB, not in git). Put it in
`local/conformance/ground/` or name its directory with
`USSP_CONFORMANCE_GROUND_DIR`; `SOURCE` has the archive's URL and the
SHA-256 of the archive and of the grid, which the workflow checks.

## Another target

`USSP_CONFORMANCE_BASE_URL` runs the suite against an existing USSP
instead of the stack. The suite's variables (the lab's
`conformance/targets/README.md`: `LAB_TOKEN_URL`, `LAB_SECRETS_JSON`,
`USSP_CONFORMANCE_CA_FILE`, the operator client and session files) come
from the environment or a `CONFORMANCE_ENV` file, and the caller states
`USSP_CONFORMANCE_AUTHORITY_PUSH` and `USSP_CONFORMANCE_SYSTEM_ID` of
that target: there is nothing to guess them from, so their absence is a
configuration error.

## The authority push is not applicable when it is off

`WS /v1/authority/flights` (`openAuthorityFlights`) is the optional
national extension of spec `02 F7`: off by default and never a condition
of any milestone (PLAN D12), the F3411 Display Provider path being the
baseline. With it off, rid-sp does not serve the path and answers 404,
as the contract says. The suite would read that 404 as a failure of
`NAT-UNAUTH`, `NAT-SCOPE` and `NAT-SUCCESS`; the target declares the
operation's checks not applicable instead (PLAN §15 Q33): the hook
appends `authority-push-off.yaml` to the lab's contract overrides
(`conformance/national/contracts/ussp.yaml`) as their `skip` table, with
the reason the report then shows. With `USSP_CONFORMANCE_AUTHORITY_PUSH=on`
nothing is skipped and the three checks run against the stream. A run
of each is recorded in `docs/RUNBOOKS/conformance.md`.

## What is not run

`F3411-SP` and `F3548-SCD` are driven by `uss_qualifier` through the
InterUSS automated-testing interfaces (RID injection,
`flight_planning` v1), which this USSP does not expose and the plan does
not foresee: they are not applicable in every run, with that reason
(PLAN §15.2 Q34, open). `F3548-CP` has no requirement set in the pinned
`uss_qualifier` (the lab's `coverage.yaml`). `NAT-PRECONDITION` and
`REG-NOPII` need fixtures the stack does not create (an operator token
and an existing resource with its ETag).
